# P6.6b4 — AI mood Service / MCP Tool

Date: 2026-11-16
Branch: `feature/p6-6-tivoo-expression-state-machine`
Baseline: `86bfb6f` (P6.6b3)
Scope: P6.6b4 only; no NAS deployment, ESP32 flash, Persona allowlist editing, or P6.6b5 hardware acceptance.

## Implementation and contract

- Added project-owned HA service `tivoo.set_mood(name)`. It is an HA/P6.6 interface, not an upstream Tivoo protocol command.
- The allowed mood set is fixed to the 14 existing presets required by ESM-C12: `happy/sad/angry/love/cool/cry/laugh/sleepy/shock/wink/sick/party/kiss/oops`. System-state presets such as `thinking/tooluse/question/standby/music` and unknown names are rejected by the service/tool schema.
- Added `ExpressionCoordinator.async_set_mood(name)`. It requires the shared current `active_generation`; with no active Tivoo voice generation it raises a clear `HomeAssistantError`. A mood is submitted as `DisplayState.AI_MOOD` with a fixed 5-second TTL through the existing intent arbiter, so generation end/cancel clears it and higher states do not pause its expiry.
- Mood keeps the existing priority contract: below active listening/thinking/tooluse/speaking (and explicit content), above follow-up wait/idle. A hidden mood that expires while speaking/tooluse is active is not replayed later.
- Added MCP/Assist tool `tivoo__SetMood` using the existing `_ServiceTool` delegation path: MCP/LLM -> HA service -> shared display coordinator. It does not call the raw command adapter or SPP layer directly.
- Tivoo Assist/MCP exposure increases from 27 to exactly 28 tools, with `SetMood` as the only addition. Existing tool names and schemas remain covered by the full Tivoo regression.
- Updated `tivoo__SetMood` description to restrict use to an active Tivoo voice reply with clear non-language emotional value; neutral replies need no mood. Updated `tivoo__SetExpression` description to reserve it for explicit user-requested visuals rather than listening/thinking/tool/speaking state.
- `set_mood` is registered/unregistered with the integration lifecycle and is not classified as replayable explicit content. No ESP32 message, SPP payload, firmware behavior, audio timing, KWS/STT/TTS lifecycle, or AstrBot phase/Stop ownership was changed.
