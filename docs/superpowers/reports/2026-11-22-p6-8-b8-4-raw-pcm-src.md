# P6.8 B8.4 — ESP32 raw PCM 24→32 kHz SRC

日期：2026-11-22。**B8.4 软件专项与双目标干净构建 PASS；实机 DSP/音质仍为 GAP。** 范围只含迁移计划 B8.4；未执行 B8.5/B8.6/B8.7/B9。

## 实现边界

- HTTP/TTS_PLAY 接受 `audio/x-tivoo-pcm-s16le-24000-mono`；原 `audio/x-tivoo-pcm-s16le-32000-mono` 和 MP3 继续支持。MIME 指定采样率，不新增设备控制字段；HTTP 响应与请求的 MIME 必须匹配。不支持的格式在开启 HTTP/输出前拒绝。
- `tivoo_audio_playback_open(generation, pcm_rate)` 使用 0 表示原 MP3 decoder、24000/32000 表示对应 raw PCM。只有生产 HTTP worker 消费该接口，已同步测试边界。
- 复用锁定 ESP Audio Effects 1.4.5 的 open/get_max_out_sample_num/process/close 及原 32 kHz 输出队列，未增加 SRC 库。
- S16LE 跨读操作保存低字节；24 kHz 按固定 1152 输入样本（48 ms）转换，HTTP 任意分块不改变 SRC 调用序列。每个 playback 对象持有独立 converter，只有 EOF 或错误/取消清理才释放。
- 锁定 API 没有单独 flush 操作。EOF 才提交不足 1152 样本的末帧；为 3:4 比例补零至 3 的倍数，输出裁至 `ceil(N × 4 / 3)`，不把补齐样本计入播放时长，不额外合成滤波尾部。32 kHz 每次 feed 直接输出，逐字节相同，不等待 SRC 帧。
- 奇数字节 EOF 返回 invalid-size；EOF/失败后的迟到数据不能再次输出。HTTP parser complete 与缓冲 drain 分离，只有最终短读/空读提交一次 converter EOF。
- 播放 UUID、session_id、stop、完成回执均复用既有 worker；每次写队列继续携带原 generation。关闭不 flush，因此取消流不会向新轮提交旧尾帧。

| 取消 | 旧 generation 流中 stop，先启动新 generation，再提交旧流余下数据：原队列拒绝；新流全零不含旧 SRC/字节状态 |

**测试能力界限：** converter/MP3 的厂商实现只有 Xtensa 预编译库；主机测试在该边界使用有历史状态的确定性 double，验证生产代码的缓冲、参数、计数、错误处理与真实输出队列 fence，不声称验证厂商滤波器的实际幅频响应、实际返回样本数或音质。扫频是合成 fixture，不冒充现场语音录音。

## 裁决、遗留与硬件 GAP

- 按用户要求在当前 `feature/p6-8-s3-local-wake` 工作区执行，不另外创建 worktree；只执行上述相关回归，未运行全量测试。
- 无独立 vendor flush API，末帧按比例补齐/裁剪，不引入新库。若实际厂商 SRC 的延迟/输出计数不符合该假设，实机专项须调整 EOF 收口；主机替身不能替代此验证。
- 审查低优先级遗留：raw PCM SRC 尚未计入原日志的 `frames/src_us`（MP3 统计仍保留）；不影响音频路径、资源释放与完成回执。本批不扩展遥测。
- **硬件 GAP：** 实际 vendor SRC 输出计数/滤波尾部、Tivoo AUX 音质、实机实时处理余量和物理完成/中断需后续获准硬件验收。本批计划明确不刷机，故未连接 NAS、未部署、未操作实际设备；不据此宣布 B9 放行。
