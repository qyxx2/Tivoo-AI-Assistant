# P6.5b10 ESP32 播放验收

生产 Tivoo Satellite 使用 `preferred_format=mp3`。NAS 上的 HA 2026.11.0 使用生产 Sherpa Matcha TTS 引擎和同一格式选项，TTS Proxy 返回 HTTP 200、`audio/mpeg` 和 47,331 字节。ffprobe 确认为 22,050 Hz 单声道 MP3，时长 4.60 秒。同一 HA 容器的转码入口也通过分段输入验证，WAV data 长度字段为 0 时，原始 PCM 可转成有效 MP3。

ESP32 按 1 KiB HTTP 读块增量解码。已锁定的 esp_audio_codec 2.6.2 解析 MP3，esp_audio_effects 1.4.5 按实际解码采样率有状态重采样。立体声先混为单声道，输出为 32 kHz Philips I²S，两个 32-bit slot 使用相同样本。PCM5102 DIN 接 GPIO27，共用 GPIO26 BCLK 和 GPIO25 WS。RX 使用 GPIO34。I²S 中断驻留 IRAM。播放 worker 固定在 core 0，AFE 继续在 core 1。

PCM 软件环容量 2,560 样本。DMA 确认最后一块 PCM 加一个 FIFO 保护块后，才发送 `completed`。STOP 清空软件环并在 TX EOF 上静音待发描述符，保留共享时钟和已进入 FIFO 的尾部。HTTP worker 独占客户端，STOP 对已建立的 socket 执行 shutdown 以唤醒读操作。连接建立阶段采用 1.5 秒传输超时，HTTP body 读等待为 8 秒。活动请求、一个待接替请求和最近 16 个播放/STOP ID 各有界，输出按 generation 隔离。

AEC R 取最终双槽 PCM，按 DMA 位置生成 16 kHz mono 参考。参考环保留 32 个 5 ms 块，补偿量默认 80 样本（5 ms）。该数值是可配置初值。需要接好 AUX 并做声学测量才能标定实际延迟。RX 丢描述符时跳过对应的参考时间并记录错位。TX 记录欠载、错过 EOF、软件环高水位以及实际交给 AFE 的参考峰值。

## 复测

在 NAS 释放 7778 和 7777 的 HA 连接后运行下列命令。使用至少 3 秒的真实 MP3。SPP 已配对连接时，脚本在播放期间发状态查询并验证回包。

```sh
python3 -u p65b10_device_acceptance.py <ESP32_IP> <fixture.mp3> \
  --http-host <NAS_LAN_IP> --require-spp
```

脚本覆盖 chunked 完整播放、重复播放 ID、过期 STOP、进行中的 HTTP/PCM 停止、新播放接替、无效 MP3、HTTP 截断、503、MIME 不匹配和 WAV 格式拒绝。记录的 STOP 延迟从发送 TVIO 指令到收到 `stopped`，测量位置在 NAS。原始镜像与测试日志保存在 NAS `/volume1/docker/tivoo-esptool/artifacts/p65b10/`。

| 主机回归 | PASS。ESP32 55 项、HA 351 项。HA 与 ESP32 测试分别运行，HA 测试插件的 socket 限制仅用于 HA 测试。 |

| 真人语音和持续 MIC 上传 | GAP。实测 AFE 在播放和 STOP 前后持续运行。当前麦克风仍有 b8 报告中记录的持续 speech 状态，未形成新的 MIC 会话来验证上传同时进行。 |

本次最终应用镜像大小 1,721,264 字节，SHA-256 为 `a1c05bef18c9c0c100864ae08a6cbefe9c760e48c1351de16558eb33b0de926b`。设备测试短暂停止 HA 以释放每端口唯一 TCP 客户端，结束后恢复 HA。

## 欠载复现与修复

在相同 ESP32 上给 HTTP 读、解码、SRC 和 PCM 入队分别计时，再重复通过 NAS 播放原样本。

| 样本 | 带计时的修复前复现 | 修复后 |
|---|---|---|
| 原生产 22.05 kHz 单声道 | 两轮 TX 欠载 53、0。一次 HTTP 读最长 81 ms，超过原软件环 80 ms 的容量。 | 相同 MP3 两轮均为 0 次 TX 欠载。 |
| 生产 HA 32 kHz 单声道 | 原生产格式需要在 ESP32 重采样。 | HA TTS Proxy 返回 `audio/mpeg`，ffprobe 确认为 32 kHz 单声道 MP3。两轮均为 0 次 TX 欠载，SRC 耗时为 0，收到 SPP 状态回包，STOP 到 `stopped` 为 102 ms。该轮间 RX 无溢出，累计参考错位增加 2 次。 |
| 原始 44.1 kHz 立体声 | 两轮 TX 欠载 250、227。每轮约 3.03 秒 PCM，解码用时 3.05–3.28 秒，SRC 另需 0.58–0.66 秒，PCM 入队用时仅 62–85 ms。 | 单纯增加预缓冲仍有 280、248 次欠载，达到持续实时供给需要改变解码负载。现有固件仍可解码此格式，但本板未验证连续播放。 |

软件环增至 5,120 样本（160 ms），达到 3,840 样本（120 ms）后开始填 TX。短音频在输入结束时直接释放预缓冲，清空后才允许发完成终态。生产 Tivoo Satellite 现在请求 HA 将 MP3 转成 32 kHz 单声道，匹配 I²S 采样率，省去 ESP32 端重采样。原始立体声可在 HA/NAS 预先转码后走同一生产路径。

跟进版 ESP-IDF 构建和 app-only 刷写校验通过，镜像 SHA-256 为 `be54d0c84fae7219b5ffb5b8d3c50afe7105005c3c84777b9f0d9055289932cb`。主机回归 ESP32 55 项，HA 351 项。生产 TTS Proxy 使用与 Satellite 一致的选项验证，固件通过独立 TVIO 客户端回放代理返回的字节。模拟和声学验收仍待现场连接 AUX。

将同一立体声样本在 NAS 转成 32 kHz 单声道 MP3 后，实机完成两轮、SPP 查询和代次隔离，STOP 到 `stopped` 为 66.6 ms。该轮仍有 3 次 RX overrun 和 3 次参考错位。播放完成和 RX 连续性分别验收。HA 配置变更已通过主机回归，生产代理已用相同选项验证，NAS 现有 Tivoo 集成此次未覆盖部署。

## 同一句生产 TTS 的 MP3 与 PCM 实机对照

NAS 用生产 Sherpa Matcha 合成一次「这是音频播放测试。请保持安静，测试即将结束。」。在 NAS 将该 WAV 转为 32 kHz 单声道 S16LE PCM，再从同一份 PCM 编码 96 kb/s MP3。两路由同一个 NAS HTTP 测试服务下发，ESP32 使用同一输出队列、预缓冲和 I²S 配置。

| 指标 | 32 kHz Mono MP3 | 32 kHz Mono S16LE PCM |
|---|---:|---:|
| HTTP 音频载荷 | 56,205 字节 | 296,656 字节 |
| 两轮完整播放的 ESP32 解码耗时 | 2,220 / 2,005 ms | 0 / 0 ms |
| ESP32 重采样耗时 | 0 / 0 ms | 0 / 0 ms |
| 两轮 TX 欠载块，317 字节 HTTP 分块 | 0 / 0 | 103 / 125 |
| 首轮发出 TTS_PLAY 到收到 completed | 4,982.4 ms | 5,745.7 ms |
| 匹配 STOP 到收到 stopped | 85.6 ms | 75.6 ms |
| 测试段 RX overrun 增量 | 9 | 202 |

PCM 测试段含两轮完整播放和 STOP、截断等故障用例，RX overrun 为整段计数差值。两路均收到播放期间的 Tivoo SPP 状态响应。原始 PCM 有效时长 4.635 秒。317 字节分块下，两轮 PCM 累计 HTTP 读等待为 5.135 / 5.274 秒，PCM 解码和重采样耗时均为零。反转顺序并在 NAS 设置 TCP_NODELAY 后，PCM 仍有 96 / 90 次 TX 欠载。STOP 数值为协议计时，AUX 实际出声仍待测。

在 NAS 设置 TCP_NODELAY 并将两路 HTTP 分块增到 4,095 字节后，两路各两轮完整播放均为 0 次 TX 欠载。PCM 首轮完成 4,965.9 ms，MP3 为 4,982.0 ms。PCM 两轮 HTTP 读等待约 3.64 秒，RX overrun 仍增加 169 次，MP3 测试段增加 5 次。该对照未证明 RX 溢出的具体机制。对这块板及本次 Wi-Fi 条件，PCM 已可稳定供给 TX，双工表现仍弱于 MP3。

复测可向 NAS 的测试脚本分别提供同源 `ab.mp3` 和 `ab.pcm --pcm`，两路均可加 `--chunk-size 4095 --require-spp`。PCM 的 TVIO 和 HTTP MIME 为 `audio/x-tivoo-pcm-s16le-32000-mono`，支持跨读块拼接小端 16 位样本并拒绝不完整的末尾样本。生产 HA Satellite 的格式设置未切换到 PCM。
